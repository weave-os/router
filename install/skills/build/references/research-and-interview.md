# Research and interview

## Research

1. Split what you need to know into independent questions: where a feature
   lives, how a similar change was done, which tests cover an area, which
   commands validate it.
2. Send one researcher per question with the researcher template. Prefer
   several small lookups over one broad one.
3. Send at least one researcher for each area the change touches, even when
   the repository looks small. Read a file yourself only to confirm a
   specific report you will act on. You make the design decisions.

## Interview

Ask the user every open question in one message, as a numbered list with a
suggested default each, so they can answer by number. Ask only what research
could not answer: product behavior, scope, tradeoffs, and approvals.

## Plan approval

Present the plan: requirements (numbered), files to change with an owner for
each, verification steps, and anything out of scope. Wait for explicit
approval before any edit. A changed plan needs approval again.
